# Simple workflow

Use this workflow only with `--simple`. It replaces the standard workflow's mandatory delegation, role boundaries, and per-stage delegate requirements. The root does preflight, inventory, eligibility, grouping, and scheduling itself. Spawn exactly one fresh subagent for each executable issue or approved group, and no preflight, triage, coordinator, review, debugging, or other subagents. The effort subagent must not spawn descendants. A skipped or blocked issue needs no subagent.

The root and effort subagent must read [workflow.md](workflow.md) for the referenced safeguards, applying the substitutions in this file wherever they conflict.

1. Parse scope, delivery mode, and effort as specified in [the skill](../SKILL.md). Perform the standard workflow's root preflight and inventory checks, except that the root determines repository-specific verification requirements itself and does not spawn a preflight delegate. Collect the complete raw inventory, including labels and dependencies. Apply the human-involvement label rule, report skipped issues and labels, and keep unresolved skipped prerequisites as blockers.
2. The root assesses dependencies, eligibility, grouping, and order from the inventory and repository evidence. Apply the standard workflow's dependency ordering and grouping rules; never group a skipped issue. In single-issue mode do not group or implement dependencies. Process efforts sequentially, waiting for prerequisites to reach the applicable delivery boundary; unrelated skipped or blocked issues do not stop eligible work. Use the inventory snapshot as the eligibility decision and report its potential staleness.
3. For each executable effort, select a model and effort according to [Subagent model selection](../SKILL.md#subagent-model-selection). Spawn one fresh subagent with the complete issue data, relevant dependency and prior effort results, repository instructions, delivery mode, starting state, verification requirements, and this workflow. Tell it to address the issue or group end to end, including any necessary investigation, implementation, verification, and delivery; do not prescribe separate delegated stages. Follow the skill's context handoff rule. The subagent reports its actual model and effort, changes, checks, delivery outcome, and blockers.
4. The subagent follows the standard workflow's workspace, validation, delivery, CI, and reporting safeguards for the selected mode, performing the work itself wherever that workflow calls for a separate role or delegate. Establish and run applicable baseline and final checks, preserve pre-existing work, and honor required checks and branch protections. Diagnose and fix failures itself, with at most five fix-and-verify cycles across local checks and CI; stop and report evidence if unresolved. Do not bypass checks or guess at an unknown root cause. In default mode use a fresh branch and worktree, create a PR and rebase-merge only after required checks pass, and verify issue closure and linear history. Since efforts run sequentially, the root grants the active subagent the exclusive integration turn. In reduced modes preserve the shared worktree and perform no GitHub writes; if an attempted effort cannot complete, stop further implementation and preserve unfinished changes.
5. The root collects each report and returns the standard workflow's final report, including skipped and blocked issues, model and effort used, fallbacks, verification, and delivery outcomes. Do not claim success for blocked or unchecked work.

Fast mode, explicit model overrides, thread exhaustion handling, and delivery boundaries from the skill remain in force. If the single subagent cannot complete an effort, report the blocker rather than spawning another agent.
