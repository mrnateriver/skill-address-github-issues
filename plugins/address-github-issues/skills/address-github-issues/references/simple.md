# Simple workflow

Use this workflow only with `--simple`. It replaces the standard workflow's mandatory delegation, role boundaries, and per-stage delegate requirements. The root does preflight, inventory, eligibility, grouping, and scheduling itself. Spawn exactly one fresh subagent for each executable issue or approved group, and no preflight, triage, coordinator, review, debugging, or other subagents. The effort subagent must not spawn descendants. A skipped or blocked issue needs no subagent.

The root and effort subagent must read [workflow.md](workflow.md) for the referenced safeguards, applying the substitutions in this file wherever they conflict.

1. Parse scope, delivery mode, `--model`, and `--effort` as specified in [the skill](../SKILL.md), rejecting invalid flags before GitHub access. Perform the standard workflow's root preflight and inventory checks, except that the root determines repository-specific verification requirements itself and does not spawn a preflight delegate. Collect the complete raw inventory, including labels and dependencies. Apply the human-involvement label rule, report skipped issues and labels, and keep unresolved skipped prerequisites as blockers.
2. The root assesses dependencies, eligibility, grouping, and order from the inventory and repository evidence. Apply the standard workflow's dependency ordering and grouping rules; never group a skipped issue. In single-issue mode do not group or implement dependencies. Process efforts sequentially, waiting for prerequisites to reach the applicable delivery boundary; unrelated skipped or blocked issues do not stop eligible work. Use the inventory snapshot as the eligibility decision and report its potential staleness.
3. At the start of each executable effort, resolve its family, model, and reasoning effort according to [Subagent model selection](../SKILL.md#subagent-model-selection): explicit `--model` first, then that effort's labels, otherwise the default fallback chain. Spawn one fresh subagent with the resolved family, selection source and evidence, fallback reasons, complete issue data, relevant dependency and prior effort results, repository instructions, delivery mode, starting state, verification requirements, and this workflow. It must retain that family through investigation, implementation, verification, remediation, and delivery; do not prescribe separate delegated stages. Resolve afresh for the next effort. Follow the skill's context handoff rule. The subagent reports its family, actual model and effort, changes, checks, delivery outcome, and blockers.
4. The subagent follows the standard workflow's workspace, validation, delivery, CI, and reporting safeguards for the selected mode, performing the work itself wherever that workflow calls for a separate role or delegate. Establish and run applicable baseline and final checks, preserve pre-existing work, and honor required checks and branch protections. Apply [Correction cycles and tooling recovery](workflow.md#correction-cycles-and-tooling-recovery): diagnose and fix failures itself, grouping repairs into at most five substantive cycles across local checks and CI. Exercise required tooling before implementation; unexpected tooling failures get one grouped recovery round excluded from that count. Do not split routine tooling fixes into separate heavyweight cycles or spawn recovery delegates. Stop and report evidence if the substantive limit or tooling-recovery allowance is exhausted with failures unresolved. Do not bypass checks or guess at an unknown root cause. Use a fresh branch and dedicated worktree per effort in default and `--no-pr` modes; `--no-commit` reuses only its dedicated run worktree. All preflight, edits, and validation also run in dedicated worktrees. In default mode create a PR and rebase-merge only after required checks pass, then verify issue closure and linear history. With `--no-pr`, commit, rebase onto the latest local `main`, resolve conflicts itself, rerun applicable checks, and fast-forward `main` with `--ff-only`. The root grants the active subagent the exclusive integration turn and coordinates it across concurrent runs. Never create merge commits on `main`. Reduced modes perform no GitHub writes; if an attempted effort cannot complete, stop further implementation and preserve unfinished changes.
5. The root collects each report and returns the standard workflow's final report, including skipped and blocked issues, resolved families and selection sources, evidence and fallback reasons, model and effort used, any within-family substitutions, verification, and delivery outcomes. Do not claim success for blocked or unchecked work.

Fast mode, model-family selection and the explicit `--model` override, the exact `--effort` override, thread exhaustion handling, and delivery boundaries from the skill remain in force. If the single subagent cannot complete an effort, report the blocker rather than spawning another agent.
